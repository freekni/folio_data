01

먼저 이것 하나 — 컨텍스트

Claude 는 정해진 크기의 작업 기억을 갖고 대화합니다. 이걸 컨텍스트라고 합니다. 읽은 파일, 실행한 명령의 출력, 주고받은 말이 전부 여기에 쌓입니다.

컨텍스트가 차면 압축(compaction) 이 일어납니다. 앞부분 대화가 요약본으로 치환되고 세부는 사라집니다. "아까 말한 그거"가 갑자기 안 통하는 이유가 이것입니다.

그래서 나머지 기능이 존재합니다. 스킬은 필요할 때만 로드해서, 서브에이전트는 읽은 원문을 따로 두고 결론만 가져와서, /clear 는 아예 비워서 — 전부 이 한 가지 문제를 다룹니다.
02

용어

세션session

Claude 를 켜고 끌 때까지의 한 덩어리. 컨텍스트는 세션 안에서만 유지됩니다.

알아둘 것 — /clear 로 비우거나, 창을 닫았다가 --continue 로 직전 세션을 이어받을 수 있습니다.
도구tool

Claude 가 실제로 하는 행동. 파일 읽기·수정, 명령 실행, 검색 등이 전부 도구 호출입니다. 대화창에 하나씩 표시됩니다.

알아둘 것 — 무슨 명령을 왜 돌리는지 보이므로, 이상하면 그 자리에서 멈출 수 있습니다.
권한 모드permission mode

파일 수정이나 명령 실행 전에 물어볼지 정하는 설정. 기본은 매번 확인입니다. 익숙해지면 수정은 자동 승인으로 돌려 속도를 올릴 수 있습니다.

알아둘 것 — 승인 프롬프트는 읽고 누르세요. 삭제·커밋·배포처럼 되돌리기 어려운 건 여기서 막는 게 유일한 기회입니다.
플랜 모드plan mode

읽기만 하고 고치지 않는 모드. 조사와 계획을 먼저 받아보고, 승인하면 그때 실행합니다.

알아둘 것 — 큰 작업일수록 이득입니다. 엉뚱한 방향으로 30분 간 뒤 되돌리는 것보다 낫습니다.
CLAUDE.mdproject rules

프로젝트 루트에 두는 규칙 파일. 매 대화마다 자동으로 읽힙니다. "이 프로젝트에선 이렇게 해라" 를 적어두는 곳입니다.

알아둘 것 — 항상 로드되므로 길면 그만큼 컨텍스트를 먹습니다. 절차는 스킬로 빼고, 여기엔 판단 기준만 남기는 게 좋습니다.
스킬skill

특정 작업의 절차를 적어둔 문서. 그 작업을 할 때만 로드됩니다. /스킬명 으로 직접 부를 수도 있습니다.

알아둘 것 — 설명 한 줄만 항상 떠 있고 본문은 걸릴 때 들어옵니다. 그래서 길게 써도 부담이 적습니다.
훅hook

특정 시점에 자동으로 실행되는 명령. 파일을 저장한 직후, 명령을 실행하기 전 같은 지점에 걸어둡니다.

알아둘 것 — Claude 가 기억해서 하는 게 아니라 시스템이 실행합니다. "매번 잊지 말고 해야 하는 일" 은 부탁보다 훅이 확실합니다.
서브에이전트subagent

별도 컨텍스트에서 조사만 하고 결론만 돌려주는 보조 Claude. 파일 수십 개를 훑어야 하는 질문에 씁니다.

알아둘 것 — 컨텍스트는 아끼지만 총 토큰은 오히려 늡니다. 그리고 요약만 받으므로 수정까지 해야 하는 일에는 쓰지 않습니다.
메모리memory

세션이 끝나도 남는 기록. 사용자의 지시나 프로젝트 특성 중 오래 갈 것들이 저장됩니다.

알아둘 것 — "앞으로 이렇게 해줘" 라고 하면 여기 남습니다. 바뀌었으면 바뀌었다고 말해주세요.
MCP외부 도구 연결

Jira·DB·사내 시스템 같은 외부 도구를 Claude 에 붙이는 규격. 붙이면 그 시스템을 직접 조회·조작할 수 있습니다.

알아둘 것 — 이 프로젝트는 현재 연결된 것이 없습니다. DB 는 MCP 대신 전용 스크립트로 접근합니다.
03

자주 쓰는 명령

입력창에 / 를 치면 목록이 뜹니다. 버전과 실행 환경(터미널 / VS Code)에 따라 있는 것과 없는 것이 조금 다릅니다.

명령하는 일언제
/clear컨텍스트를 비우고 새로 시작작업 하나가 끝날 때마다. 가장 자주 쓰게 됩니다
/compact지금까지 대화를 요약본으로 압축맥락은 이어가야 하는데 컨텍스트가 찰 때
/rewind파일을 이전 상태로 되돌림수정이 잘못됐을 때
/model모델 변경가볍고 빠르게 / 어렵고 정확하게 사이 조절
/config테마·모드 등 설정처음 한 번
/hooks훅 목록 확인·수정훅이 안 걸리는 것 같을 때
/mcp외부 도구 연결 상태MCP 를 쓸 때
/init코드베이스를 분석해 CLAUDE.md 생성새 프로젝트를 붙일 때
/cost사용량 확인궁금할 때
daebonew 전용 명령 — /xfdl-write, /screen-check, /java-gv10-diff, /dev-setup. 7번 항목에서 설명합니다.
04

모델과 생각 깊이

같은 Claude Code 라도 어떤 모델로 도는지에 따라 결과와 속도가 달라집니다. /model 로 바꿉니다. 조합이 세 가지 축으로 나뉩니다 — 모델, 생각 깊이, 출력 속도.

모델

모델성격언제
Fable 5 가장 강력, 가장 느리고 가장 비쌈 초고난도 코딩, 장시간 작업, 복잡한 분석
Opus 5 강력, 느리고 비쌈 복잡한 원인 분석, 대규모 리팩터링, 설계 판단
Sonnet 5 균형 일상 작업 대부분 — 화면 수정, 소규모 기능
Haiku 4.5 가볍고 빠름 단순·반복 작업, 대량 처리
모델 이름 뒤의 [1m] — 컨텍스트 창을 100만 토큰으로 늘린 변형입니다. 1번 항목의 "작업 기억"이 그만큼 커져 압축이 훨씬 늦게 옵니다. 큰 파일을 여럿 다룰 때 유리합니다.

생각 깊이 effort

답하기 전에 얼마나 오래 따져볼지입니다. low · medium · high · xhigh 네 단계가 있고, 올릴수록 정확해지지만 느려집니다. 어려운 디버깅이나 설계에서는 high 이상이 체감됩니다.

Fast mode /fast

가장 흔한 오해가 여기 있습니다. Fast mode 는 작은 모델로 낮추는 게 아닙니다. Opus 를 그대로 쓰되 출력만 빠르게 하는 것입니다. 품질을 포기하지 않고 속도를 얻습니다. Opus 5 / 4.8 에서 쓸 수 있습니다.

실전 감각 — 대부분은 Sonnet 으로 충분합니다. "몇 번 시켰는데 계속 헛짚는다" 싶으면 모델을 올리거나 생각 깊이를 올려보세요. 반대로 단순 반복인데 느리다면 낮추면 됩니다. /model 은 대화 중에도 바꿀 수 있습니다.
05

실무 습관 여섯

컨텍스트

작업이 끝나면 /clear

화면 하나 고치고 다음 작업으로 넘어갈 때 비우세요. 앞 작업의 파일이 계속 남아 있으면 압축이 빨리 오고, 엉뚱한 앞 맥락에 끌려가기도 합니다.

방향

큰 작업은 계획부터 받으세요

"이거 어떻게 할 건지 먼저 말해줘" 한마디면 됩니다. 코드를 다 짜놓고 방향이 틀린 걸 발견하는 것보다 훨씬 쌉니다.

안전

승인 프롬프트를 읽으세요

특히 삭제·커밋·배포·DB 쓰기. 되돌리기 어려운 일을 막을 수 있는 지점이 거기 하나뿐입니다. 습관적으로 엔터를 치지 마세요.

검증

"다 됐습니다" 를 그대로 믿지 마세요

테스트를 돌렸는지, 무엇으로 확인했는지 근거를 보세요. 근거 없이 완료라고 하면 "어떻게 확인했어?" 라고 되물으면 됩니다.

구체성

파일·화면 이름을 같이 주세요

"그 화면 안 떠" 보다 "DHB_REQ2DETAIL 이 안 떠, 로그는 이거" 가 훨씬 빠릅니다. 찾는 데 쓰는 컨텍스트가 줄고 오답도 줄어듭니다.

기록

반복될 지시는 규칙으로 남기세요

같은 말을 두 번 이상 하고 있다면 "앞으로 항상 이렇게 해줘" 라고 말해주세요. CLAUDE.md 나 메모리에 남아 다음 세션에도 적용됩니다.

06

Claude 가 못 하는 것

기대치를 미리 맞춰두면 "왜 안 해주지" 로 시간 버릴 일이 없습니다.

불가사람이 직접 해야 하는 것
  1. VS Code 화면 조작 — Java: Reload Projects 같은 명령 팔레트 실행, 버튼 클릭. 파일은 고칠 수 있지만 UI 는 누를 수 없습니다.
  2. 프로그램 설치 — 사내 표준 배포본이 따로 있는 경우가 많아, 이 프로젝트에서는 안내만 하고 설치는 하지 않도록 규칙을 정해뒀습니다.
  3. 계정·비밀번호 — SVN 로그인, 라이선스 등록 같은 자격증명은 본인 것입니다.
  4. 화면을 눈으로 보는 것 — 렌더링 결과는 모릅니다. 다만 스크린샷을 붙여넣으면 읽을 수 있습니다.

반대로 로그·에러 메시지는 통째로 붙여넣는 게 가장 효율적입니다. 요약해서 전달하면 정작 원인이 담긴 줄이 빠지는 경우가 많습니다.

07

daebonew 에서 추가로 알 것

스킬 네 가지

스킬언제 걸리나
/xfdl-write.xfdl 신규·수정 — 패턴 선택, 공통 골격, DB 등록이 필요해지는 변경
/screen-check화면 등록 상태 점검 — 화면이 안 열리거나 그리드가 비어 보일 때
/java-gv10-diff.java 수정 — gv10 동일 파일과 대조
/dev-setup개발환경 세팅 — 점검하고 남은 할 일을 알려줌

직접 부르지 않아도 해당 작업을 시작하면 자동으로 걸립니다.

자동으로 도는 것 — 시키지 않아도 됩니다

  • .xfdl 저장 → .xfdl.js 생성 — src/main/webapp/ 에 산출물이 자동으로 만들어집니다. 원본만 고치면 화면이 안 바뀌는 함정을 훅이 막아줍니다.
  • 신규 화면 감지 — SVN 미등록 .xfdl 이면 DB 등록 점검을 하겠냐고 물어봅니다.
  • .claude/INDEX.md 갱신 — Claude 관련 파일이 늘면 목록이 자동으로 맞춰집니다.

안전장치

  • DB 는 전용 스크립트로만 — 기본 읽기 전용이고, 접속 대상이 application.properties 와 다르면 아예 붙지 않습니다. 운영 서버는 차단입니다.
  • sqlcmd 직접 호출 차단 — 위 가드를 우회하기 때문입니다.
  • 계정·비밀번호는 출력하지 않습니다 — 복호화한 값은 실행 중 메모리에만 둡니다.
주의커밋하면 안 되는 파일
  1. .classpath, .project, .settings/ — STS 와 VS Code 가 번갈아 덮어쓰는데, 안에 Windows 사용자명과 확장 버전번호가 박힌 절대경로가 들어갑니다. 커밋하면 다른 사람 전원의 Gradle 동기화가 깨집니다.
  2. CLAUDE.md, .claude/ — svn 무시 대상으로 이미 등록해뒀습니다 (r91886). svn update 만 하면 자동 적용됩니다.
08

Windows 함정

이 프로젝트에서 실제로 겪은 것들입니다. 알아두면 원인을 빨리 찾습니다.

증상원인 / 대응
.ps1 이 실행되지 않음 실행 정책이 Restricted. powershell -ExecutionPolicy Bypass -File … 로 실행하거나, Set-ExecutionPolicy -Scope CurrentUser RemoteSigned 를 한 번 설정
압축본에서 푼 .ps1 이 계속 막힘 인터넷에서 받은 파일 표시(MOTW). 압축 파일 속성 → 차단 해제 후 풀거나 Unblock-File
파일을 고쳤더니 전체가 변경으로 잡힘 줄바꿈이 CRLF → LF 로 바뀐 것. 대부분의 소스가 CRLF 라 sed -i 같은 도구가 통째로 바꿔버립니다
한글이 ??? 로 깨짐 콘솔 코드페이지(CP949) 문제. 파일 자체는 멀쩡한 경우가 많습니다
화면은 뜨는데 그리드가 비어 있음 정상입니다. 그리드 컬럼은 .xfdl 이 아니라 DB 에서 옵니다
화면이 아무 반응 없이 안 열림 DB 미등록. 에러도 로그도 안 남습니다. /screen-check 로 확인
PowerShell 과 Bash 를 섞어 쓰는 환경입니다. 두 셸은 문법이 달라서, 한쪽 문법을 다른 쪽에 넣으면 에러가 나는 게 아니라 조용히 다른 일을 합니다. 명령을 복사해 쓸 때 어느 셸용인지 확인하세요.

더 자세한 내용은 저장소 안에 있습니다 — 파일 목록과 용도는 .claude/INDEX.md, 환경 세팅 절차는 .claude/project/daebonew/dev-setup-guide.md, 화면 작성 규약은 .claude/docs/nexacro-screen-conventions.md.
